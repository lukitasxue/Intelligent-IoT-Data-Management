\# AI: 025 — Analytics Integration Failure Behaviour \& Contract Impact



\## 1. Objective

Define the operational and schema contract behaviour of the Analytics Integration layer when handling upstream service errors, malformed responses, empty outputs, and partial service availability across Models and Correlation microservices.



\---



\## 2. Failure-Behaviour Matrix



| Scenario ID | Upstream Component | Condition / Trigger | HTTP Status (Internal) | Analytics Integration Output `status` | `alerts\[]` Payload | `errors\[]` Entry | Logging Level |

| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| \*\*SC-01\*\* | Both | Normal execution, alerts found | 200 OK | `"success"` | Contains alert objects | Empty (`\[]`) | `INFO` |

| \*\*SC-02\*\* | Correlation / Models | Normal execution, zero alerts found | 200 OK | `"success"` | Empty (`\[]`) | Empty (`\[]`) | `INFO` |

| \*\*SC-03\*\* | Correlation | Legacy 500 on malformed input (missing keys) | 500 / 400 | `"partial\_success"` (if Models OK) / `"failed"` | Preserves Models alerts | `\[{ "source": "correlation", "code": "MALFORMED\_REQUEST", "message": "Missing required fields" }]` | `ERROR` |

| \*\*SC-04\*\* | Models / Correlation | Service timeout / Unreachable connection | Connection Error / 504 | `"partial\_success"` (if one OK) / `"failed"` | Contains available alerts from healthy service | `\[{ "source": "<service>", "code": "SERVICE\_UNAVAILABLE", "message": "Connection refused" }]` | `ERROR` |

| \*\*SC-05\*\* | Models / Correlation | Incompatible response schema (Contract violation) | 200 OK | `"partial\_success"` / `"failed"` | Drops invalid source alerts; keeps valid source alerts | `\[{ "source": "<service>", "code": "SCHEMA\_VIOLATION", "message": "Schema format mismatch" }]` | `WARN` / `ERROR` |

| \*\*SC-06\*\* | Ingestion | Empty input dataset provided to pipeline | 400 Bad Request | `"failed"` | Empty (`\[]`) | `\[{ "source": "analytics\_integration", "code": "EMPTY\_DATASET", "message": "Zero telemetry rows provided" }]` | `WARN` |



\---



\## 3. Expected Partial-Success Behaviour

When one upstream analytics service succeeds while the other fails:

\* \*\*Outer Status\*\*: Set to `"partial\_success"`.

\* \*\*Alerts Preservation\*\*: Valid alerts generated by the functioning service are fully retained in `alerts\[]`.

\* \*\*Errors Recording\*\*: The failed service generates a structured error entry inside `errors\[]` containing `source`, `code`, `message`, and timestamp.

\* \*\*Downstream Delivery\*\*: The Express backend receives an envelope rather than a pipeline crash, allowing the dashboard to display available alerts while surfacing degraded analytics warnings.
